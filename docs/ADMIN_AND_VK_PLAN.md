# Административный кабинет Санко и проверка знакомых ВК

**2 ноября 2026 · текущий этап: админ-статистика и просмотр переписок.**

## Реализовано

Отдельный Worker `sanko-chat-api` обслуживает:
- `GET /admin/stats` — статистика запросов Санко: сегодня, вчера, 7 дней, месяц, отдельный IP, число уникальных IP за день, свободная квота 500/15 000/100, график за 30 дней, распределение ответов по моделям и статусам, число диалогов;
- `GET /admin/chats` — поиск по репликам, список диалогов с пагинацией и просмотр всей переписки за выбранные 30 дней;
- `POST /admin/stats/data`, `POST /admin/chats/list`, `POST /admin/chats/thread` — закрытые API, которые работают только после проверки токена.

Интерфейс ориентирован на привычный раздел администратора Олешки: две страницы, поиск разговоров, те же принципы учёта запросов и 30-дневного хранения текстов. В отличие от архива Олешки, **журнал Санко только в собственной D1** `GUARD_DB = heroes-chat-sanko`; `DIARY_DB` с дневником Олешки административный код не читает вообще. Ещё не реализованы удаление переписок и экспорт — задача состояла в просмотре и учёте.

## Доступ и безопасность

- В Cloudflare у **sanko-chat-api** требуется собственный секрет **`ADMIN_UPDATE_TOKEN`**: случайное длинное значение не короче 32 символов. Старый секрет Олешки не копируется и не публикуется.
- Сам HTML доступен по ссылке без авторизации, но в нём **нет пользовательских данных**; информация берётся только по `Authorization: Bearer <token>`, переданному на тот же домен Worker по HTTPS. Сервер сравнивает хеши секретов, не сохраняет их в логах.
- В браузере токен находится только в поле формы и в памяти открытой страницы: **не пишется** в `localStorage` или `sessionStorage`. После закрытия вкладки потребуется повторный ввод.
- Запросы API с чужим Origin отклоняются даже при известном токене. Ответы с персональным содержимым не кешируются. В динамическом интерфейсе используется `textContent`, а не `innerHTML`. Действуют CSP, X-Frame-Options и Referrer-Policy.
- Все административные операции **только чтение**. Поля `client_hash` из D1 не передаются в браузер, показываются лишь агрегированные числа. Нет SQL-операций к таблицам Олешки.
- Поскольку в журнале встречаются личные сообщения, доступ к токену должен оставаться только у владельца проекта. Не вставлять токен в ссылку или репозиторий.

**Подключение:** Cloudflare Dashboard → Workers & Pages → `sanko-chat-api` → Settings → Variables and secrets → Add variable → выбрать **Secret** → `ADMIN_UPDATE_TOKEN` → сохранить/Deploy. Другие секреты (`GEMINI_API_KEY`, `IP_HASH_SECRET`) уже настроены и не требуют изменений.

После развёртывания и добавления секрета:
1. Открыть `https://sanko-chat-api.boysinger2008.workers.dev/admin/stats`, ввести токен, убедиться в цифрах;
2. Открыть `https://sanko-chat-api.boysinger2008.workers.dev/admin/chats`, ввести тот же токен, открыть несколько разговоров;
3. Проверить, что неверный токен ничего не показывает.

**Статус:** код и тесты в GitHub. Реальное наличие нового секрета и работа развёрнутых административных страниц должны быть подтверждены после настройки Cloudflare.

## Следующий отдельный этап: узнавание знакомых ВКонтакте

После создания отдельного VK Mini App чата Санко и получения его **собственного** `VK_APP_ID` / `VK_APP_SECRET`:

1. Использовать уже существующий серверный механизм проверки подписанной строки запуска `vkLaunch` в `POST /api/session`. Без валидной подписи нельзя доверять переданному посетителем VK ID, имени или заявленному статусу.
2. Настроить **личный VK ID Санко** и допустимые сервисные/пользовательские токены с разрешениями для проверки списка его друзей и личных подписчиков. Не использовать VK-идентификатор и отношения Олешки в качестве отношений Санко.
3. Как в чате Олешки, различать три статуса **друг / подписчик / незнакомец** и возвращать их в сессию только после серверной проверки. Для сетевых ограничений/отказов ВК нужна безопасная деградация без ложного утверждения, что пользователь — друг.
4. Держать кеш отношений в **персональных ключах `sanko:vk:*`** и при необходимости в **отдельных таблицах D1 Санко**, а не в хранилище Олешки; проверять доступность методов VK и права токенов на практике.
5. После подтверждения работоспособности добавить приветствия Санко, учитывающие степень знакомства, и административную страницу проверки доступности друзей/подписчиков; затем тестировать внутри Mini App и публикацию ВК.

**Не начинать автоматически VK-проверку до появления VK Mini App, его настоящего ID и подтверждённого способа доступа к спискам друзей/подписчиков Санко.** Нельзя угадывать VK-идентификатор героя или обещать доступ к закрытым спискам без проверки разрешений API.
