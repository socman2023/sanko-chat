## Этап 4.2 — сервер Санко (исходники в GitHub)

- Созданы `worker/src/index.js` и `worker/src/lib.js` — самостоятельный Worker `sanko-chat-api`, маршруты `GET /health`, `POST /api/chat`, `POST /api/session`.
- Разделены: общий `AI`, общий Vectorize `KNOWLEDGE` → `heroes-knowledge`, общий KV `CURRENT_CONTEXT` → `heroes-chat-current` с префиксом `sanko:`; **отдельная новая D1** `heroes-chat-sanko` в проекте Санко.
- Персональные и общие векторы ищутся только с фильтром `character in ["shared","sanko"]`; после ответа Vectorize данные повторно проверяются по метаданным.
- Реализована привязка вопросов к дням: «сегодня», «вчера», «позавчера», ISO и русские даты. Датированный запрос не смешивается с записями других дней, как в исправлении Worker Олешки 3.9.1.
- Лимиты чата Санко в коде: **500/15 000/100**. Используется D1-учёт с атомарной записью допуска.
- Доступ к Gemini с последовательным резервированием моделей, но API key Санко и его Google AI project будут отдельными от Олешки.
- Утверждённый персональный профиль должен передаваться через серверный ключ KV `sanko:profile:v1`; пока ключ отсутствует, чат возвращает 503 **без расхода квот и Gemini**.
- Миграция `worker/migrations/0001_init.sql` предназначена **только для новой D1 Санко**, не применять к `heroes-chat-guard`.
- Добавлены тесты `worker/tests/lib.test.mjs` и `worker/tests/server.test.mjs`. Локальная логика времени и фильтров дополнительно проверена; тесты взаимодействия с живым Cloudflare и Gemini пока не проводились.
- Корневая конфигурация `wrangler.toml` готова к первоначальному развёртыванию **нового Worker `sanko-chat-api`** без bindings и секретов. Начальный Worker будет отвечать `GET /health` с `configured:false` и отклонять сообщения 503 до подключения собственной D1, профиля Санко и общих знаний.
- [README Worker и порядок предстоящего запуска](../worker/README.md).
- **Олешка 3.9.1, его D1, KV, Vectorize и сайт не менялись**.

## Этап 4.3 — создание D1 Санко (начат 2 ноября 2026)

- Подтверждён существующий в Cloudflare Worker `sanko-chat-api`; домен workers.dev активен, сборка успешна.
- В Dashboard пока показано 0 bindings. Это ожидаемо до создания отдельных данных и настройки общего доступа.
- **Первое действие:** создать **только** новую D1 `heroes-chat-sanko` через Storage & Databases → D1 SQL Database → Create Database.
- Следующее действие после появления ID: внести реальный `database_id` новой базы в **корневой** `wrangler.toml` с binding `GUARD_DB`. Не использовать ID `heroes-chat-guard`.
- Затем применить `worker/migrations/0001_init.sql` к `heroes-chat-sanko` и проверить структуру.
- Далее подключить существующие Workers AI, Vectorize `heroes-knowledge` и KV `heroes-chat-current` без изменения их содержимого.
- После разрешения профиля Санко настроить его KV-ключи и секреты. До завершения настроек клиент остаётся макетом.
