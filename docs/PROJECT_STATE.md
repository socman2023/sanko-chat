## Этап 4.8 — полный текст дневника без обрезки (02.11.2026)

- **Коренная ошибка была допущена в Worker Санко, а не в обновлении дневника Олешки.** Ассистент изначально установил обрезку `source_text` до 1900 символов, затем ошибочно заменил её «почти полным» текстом до 16 000, оставил общий порог 30 000 символов и `systemText().slice(0,62000)`. Из-за этого Санко упускал вторую половину полноценной записи.

Значит, опубликованная запись уже находилась в D1. Версия Worker на момент проверки — `sanko-worker-0.2.1`.
- **Постоянное правило проекта, подтверждённое автором:** вечерняя запись обычно публикуется в **20:00 МСК**, а её штатная проверка выполняется **в 20:30 МСК всегда**. Не объяснять отсутствие второй части записи гипотезами о трёхчасовой задержке, когда D1 прямо подтверждает своевременную загрузку.

## Этап 4.13 — устранён 503 в административной базе знаний (02.11.2026)

- Старые тесты выдавали фальшивые значения в ответ на любой запрос. Теперь добавлен `worker/tests/canon-sqlite.test.mjs` на **настоящем SQLite** (node:sqlite), который проверяет создание таблицы, начальный статус, импорт, обновление статуса, повторную загрузку и кириллический поиск; это не замена облачному E2E, но позволяет ловить ошибки SQL до деплоя.

## Этап 4.26 — точный fallback Gemini при model-not-found и HTTP-диагностика (04.11.2026)

- Автор предоставил реальные отчёты о двух неудачных разговорах Санко: каждая попытка содержала только `gemini-3.5-flash-lite · service_unavailable · расход неизвестен`. Резервные модели не были вызваны. Код подтверждает причину: `classifyProviderError` присваивал 404 и другим HTTP 4xx `retryable:false`, а `answerWithGemini` прекращал каскад по `!result.retryable`.
- По актуальной документации Gemini для **model_not_found (HTTP 404)** Google рекомендует перейти на другую модель. Исправление: **404 и 501** теперь классифицируются как `model_unavailable` с `retryable:true`, 409 тоже допускает резервирование. **400, 401, 403** по-прежнему останавливают каскад (некорректный запрос, неверный ключ, права/доступ): слепое повторение может лишь расходовать лимиты. Безусловный fallback для всех ошибок не введён.
- Для новых серверных ошибок (кроме 429, поведение которых сохранено) существующая `token_usage.result` записывает `kind:HTTP` (например, `model_unavailable:404`, `service_unavailable:400`) без миграции D1 и без сохранения текста ответа API/ключей. Исторические `service_unavailable` не позволяют восстановить прежний HTTP-статус — причину тех конкретных 3 событий пока невозможно уточнить.
- Пользовательский интерфейс Санко допускает ответ `model_unavailable`, Worker помечен `sanko-worker-0.6.10`, версия в живом проверочном workflow синхронизирована. Тесты: при 404 в основной модели следующая модель отвечает; при 400/401/403 запасные модели не вызываются и код ошибки фиксируется.
- Не изменялись подбор фактов мира, профиль, длинные тексты дневника, лимиты, API ключи и другие персонажи. **Средний вход ~35 091 токен** требует отдельной оптимизации с проверкой канонической точности; это ещё не исправлено. После публикации подтвердить live `/health` версия 0.6.10 и проверить новый вызов без реальных рисков для личных переписок.
