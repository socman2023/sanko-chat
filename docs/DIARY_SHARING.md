# Общий дневник событий для Олешки и Санко

**Обновлено:** 2 ноября 2026 года  
**Кодовое подключение:** выполнено. **Live-проверка нового развёртывания Cloudflare:** ожидается.

## Принятый канон

Олешка и Санко обычно находятся вместе и участвуют в одних событиях. Санко **пользуется всей информацией дневника Олешки**, но говорит об общих событиях **от собственного лица**, как участник, без обязательных оговорок «Олешка писал» или «прочитал у Олешки».

**Исключения — реальные расставания** (например, Санко улетал за Айоаном), действия Олешки наедине, его личные чувства, сны, внутренние мысли и события, при которых присутствие Санко явно исключено. В этих случаях Санко не придумывает своё участие; сведения из дневника остаются известны ему, хотя личным опытом не становятся.

Приоритет этих правил — прямое решение автора от 2 ноября 2026 года. Не возвращаться к прежнему правилу «по умолчанию всё из дневника — только со ссылкой на автора».

## Инфраструктура: один автоматический импорт, два независимых чата

- Работающий Worker Олешки **v3.9.1** выполняет штатное обновление дневника ВК. **Для вечерней записи постоянная проверка — в 20:30 МСК**, типичное время публикации — **20:00 МСК**. Проверка 02.11.2026 подтвердила публикацию в 20:00:01 и загрузку в D1 в 20:30:29. Другие задачи Cron не меняются.
- Публикации из ВК сохраняются в существующей D1 **`heroes-chat-guard`**, таблица **`oleshka_vk_diary`**; авторский VK owner_id = `850667816`.
- В **корневой `wrangler.toml` репозитория Санко** добавлен второй D1 binding:
  - `DIARY_DB` → `heroes-chat-guard` → `3d356f87-0894-4c03-8dac-a3b82ae2ed6c`.
- Собственная база Санко не меняется: `GUARD_DB` → `heroes-chat-sanko` → `d566ac31-19ce-463f-80e5-6ed1b0d56b16`.
- Worker Санко не сканирует VK самостоятельно, не добавляет Cron и не копирует записи в свою D1. Не изменены настройки и Worker Олешки.
- Общий Vectorize `heroes-knowledge` остаётся с фильтром `shared|sanko` для личных и мировых документов. А дневник доступен напрямую по `DIARY_DB`: фильтр Vectorize не отсекает события, известные обоим героям.

## Как читает Санко

Функция `loadPublishedDiary()` использует **только SELECT** из `oleshka_vk_diary`. Она исключает помеченные как `excluded` / `rejected` записи.

- Вопрос о конкретной дате: **все опубликованные записи за выбранный день**, без SQL LIMIT; полный текст каждой.
- Вопрос без даты: сначала **все записи за сегодня**, затем вчерашние, затем подходящие тематические и недавние архивные записи; повторы исключаются. Исторический поиск ограничивает **количество найденных записей**, но не урезает их текст.
- **Каждая выбранная дневниковая запись передаётся в Gemini дословно и целиком.** В Worker Санко нет ограничения 1900/16000 символов на запись, общего порога 30000 символов и обрезки всей системной инструкции по 62000. Полнота сегодняшней записи важнее экономии токенов; объём многолетнего архива регулируется только отбором релевантных публикаций.
- Это **поиск по полному хранилищу дневника**, а не полная загрузка всех текстов в один запрос. Для сложных поисковых вопросов возможны промахи, которые надо выявлять тестами.
- **Дата публикации** и **дата описанного события** — не всегда одно и то же.
- Чтение D1 не имеет технического права «read-only» на уровне binding: безопасность обеспечивается тем, что в коде `DIARY_DB` применяется только к SELECT. Не добавлять туда операции записи. Прямое подключение не раскрывает D1-контент в браузере.

## Тестирование

- `GET https://sanko-chat-api.boysinger2008.workers.dev/health`: `character:"sanko"`, `configured:true`, `diaryConnected:true` — проверяет наличие binding.
- `POST /api/chat`: `knowledge.diaryPosts` — фактическое число добавленных к конкретному запросу записей.
- Простой вопрос «А как мы перелетели через Стену?» должен вызвать собственный рассказ Санко, без шаблона «Олешка писал».
- Контрольный вопрос о днях, когда Санко летал за Айоаном, не должен приводить к ложному рассказу о присутствии рядом с Олешкой.
- Проверка прежней записи должна показывать, что поиск доступен не только по последним десяти публикациям.
- Успешная диагностика 02.11.2026 показала, что вечерняя запись уже была в D1 (`postsToday=1`): ошибка с пропуском дневных событий была **в обрезке текста внутри Worker Санко**, а не в синхронизации. После развёртывания версии `sanko-worker-0.2.2` проверить, что он пересказывает и конец этой записи.
- GitHub Actions тестирует SQL SELECT-only, границы доступа, тематический поиск и новую речевую установку. Успешные тесты **не заменяют** проверки Cloudflare и реальных реплик Санко.

**Рабочая версия канонического профиля Санко в KV пока имеет статус REVIEW**. Речевые и фактологические тесты продолжатся в настоящем чате.
