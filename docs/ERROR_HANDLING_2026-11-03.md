# Безопасная обработка неполадок в чате Санко — 03.11.2026

## Поставленная задача
Посетитель не должен видеть технические ошибки Gemini, Cloudflare или JSON при
исчерпании квот, перегрузке модели и временных проблемах связи. Все сообщения
на обычной веб-странице должны оставаться человеческими репликами Санко.

## Реализация
**Worker:** `worker/src/error-policy.js` + обновлённый `worker/src/index.js`
с версией `sanko-worker-0.5.0`. Для каждой отказавшей модели анализируются
HTTP-статус и структурированные поля `error.status`, `error.details`.
`RESOURCE_EXHAUSTED` / `QuotaFailure` после HTTP 429 означает
`provider_quota`; обычная перегрузка / сбой — `provider_busy`.
Данные Gemini не попадают в публичное поле `reply`, только вид ошибки
в приватный журнал. При 429 для конкретной модели — best-effort перерыв
30 секунд (rate) или 5 минут (quota) **на текущем Worker isolate и API-ключе**,
не глобальная блокировка. Резервные модели вызываются не больше одного раза
каждая. Без подтверждённого `retryAt` сервер не придумывает время
возобновления квоты Gemini.

**Публичный формат ошибок:**
`{error:"provider_quota|provider_busy|service_unavailable|response_blocked",reply:"короткая реплика Санко"}`.
Серверные статусы остаются настоящими (503/422), чтобы можно было диагностировать
ошибки на техническом уровне.

**Внутренние ограничения чата:** 100/IP/сутки, 500/сутки, 15000/месяц.
`HTTP 429` с `error=quota_exhausted`, `reply` и подтверждённым
`retryAt`; в отличие от Gemini квота чата имеет точное время сброса.

**Интерфейс:** `assets/app.js` показывает `reply` Санко даже при 503,
421/422 или 429, а если пришёл не JSON (например, HTML Cloudflare), выводит
безопасную реплику Санко. Неотправленный вопрос остаётся в поле ввода.
Служебные ответы записываются в браузере с отдельным типом `role=notice`,
выглядят как сообщения Санко, **не отправляются модели в `history`**.
История обычных разговоров не теряется. Внутренний лимит блокирует
отправку только до подтверждённого `retryAt`, после чего поле
разблокируется автоматически, включая страницу, оставленную открытой.
Новый разговор не сбрасывает реальный серверный лимит.

## Тестирование
- GitHub Actions `Sanko source tests`, ветка `main`: все тесты прошли
  после изменения клиента, Worker и файлов проверок.
- Тестировались: квота Gemini с HTTP 429, HTML-ответ 503, блокировка SAFETY
  без перехода на другую модель, резервный переход, отсутствие технических
  диагностик в `reply`, отделение служебных уведомлений от истории.
- Изменения `GUARD_DB`, `DIARY_DB`, `KNOWLEDGE`, `CURRENT_CONTEXT`,
  ключей, Cron и дневника не требуются.

**Состояние проверки:** реальная версия рабочего Worker Cloudflare не могла
быть независимо запрошена из текущей инструментальной среды. Наличие
пройденного GitHub Actions доказывает результат тестирования коммита,
но не успешное внешнее Cloudflare развёртывание.
