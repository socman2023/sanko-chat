# Санко — учёт Gemini-токенов (Free Tier)

## Что реализовано

- В Worker после каждой фактической попытки Gemini API читается `usageMetadata` с `promptTokenCount`, `candidatesTokenCount`, `thoughtsTokenCount`, `cachedContentTokenCount`, `totalTokenCount`.
- Неуспешные запросы и резервные модели учитываются отдельными строками. Если метаданные отсутствуют, токены считаются **неизвестными**, а не нулевыми.
- `cachedContentTokenCount` — часть входного контекста и не прибавляется повторно. Общий расход берётся только из `totalTokenCount`.
- Для Санко используется исключительно его D1 `heroes-chat-sanko`, таблица `token_usage`, без текстов переписки, IP-адресов и API-ключей.
- В существующем защищённом `/admin/stats` появляются показатели сегодня, 7 дней, месяц, среднее на измеренный вызов, разбивка по моделям и дням. Работа без миграции не должна прекращать общение: админ-панель покажет «недоступно».
- Ни платные тарифы, ни биллинг, ни новые сервисы не подключаются. Лимиты Worker (500/15 000/100) не меняются.
- Это **история фактического использования**, а не счётчик остатка бесплатной квоты Google. Дневные квоты Gemini считаются по собственным правилам и могут не совпадать со временем сброса внутреннего лимита чата.

## Развёртывание — вручную в Cloudflare

Важно: изменения в GitHub не устанавливают автоматически D1-таблицу или Worker на Cloudflare.

1. В Cloudflare D1 открыть **только** базу `heroes-chat-sanko` (не `heroes-chat-guard`). Выполнить SQL из `worker/migrations/0002_token_usage.sql`, используя SQL Console. Ранее `0001_init.sql` применяли вручную; не запускать всю цепочку миграций автоматически. Создание таблицы и индексов безопасно при повторном выполнении благодаря `IF NOT EXISTS`.
2. После успешного прохождения GitHub Actions установить `sanko-worker-0.5.1` из обновлённого кода в Cloudflare, сохранив существующие bindings, ключи и настройки. Перед заменой сохранить текущий deployment для возможного отката.
3. Проверить `GET /health` и версию Worker, открыть `/admin/stats`, ввести уже действующий секрет `ADMIN_UPDATE_TOKEN` Санко. Если таблица есть и запросов пока не было, показания должны быть нулевыми.
4. Задать Санко один обычный вопрос, обновить страницу. Проверить количество вызовов Gemini и расход; при переключении модели один вопрос может дать несколько строк статистики.
5. Если панель показывает недоступность учёта, проверить наличие таблицы и прав D1; диалоги должны оставаться доступными.

## Пределы точности

- Исторические токены до установки счётчика не восстановить.
- Все API-попытки пишутся независимо от того, был ли получен ответ. Для вызовов без `totalTokenCount` расход обозначается как неизвестный.
- Данные токенов хранятся до 95 дней; видны 30 последних дней и текущий календарный месяц.
- Ошибка записи в D1 не должна блокировать диалог. В Cloudflare Logs появляется только служебное предупреждение, без реплик или секретов.
- Текущие параметры Free Tier необходимо проверять в Google AI Studio; сумма токенов в панели не является оставшимся лимитом.

## Как тестируется

`npm test` в корне репозитория выполняет набор тестов Worker. Включены проверки: metadata/null, fallback, заблокированный ответ, отсутствие таблицы, защищённая статистика и её агрегация. Это тесты с имитацией Gemini, не расходующие реальную бесплатную квоту.
